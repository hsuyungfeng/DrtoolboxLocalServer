<objective>
Build `HybridRetriever` — a small fusion service combining `SimpleIndex.get_scored_chunks()` (sparse, left untouched) with `SemanticSearch.search()` (dense, made real in Plan 10-01) via Reciprocal Rank Fusion — and swap it into `RAGEngine._get_context()` as the sole retrieval call for both `special` and `general` routes, with a mandatory fallback to today's sparse-only behavior on any Chroma failure (D-05, D-06). This is Stage 2 of the phase, and the highest-stakes plan: it changes the live query path for a production clinic chatbot answering real patients.

Purpose: Until this plan, RAG retrieval quality is capped by sparse keyword/n-gram matching alone; the freshly-populated Chroma dense index (Plan 10-01) is not yet consulted for any real answer. RRF fusion lets both retrieval signals contribute without needing to normalize incomparable score scales (BM25/n-gram vs cosine similarity).
Output: `src/rag/hybrid.py` (new), `_get_context()` in `src/rag_engine.py` now queries both retrievers and fuses results, with a human spot-check checkpoint before this is considered production-ready.
</objective>

<assumption_delta_decision>
**Noun now primary:** the answer-context retriever called from `RAGEngine._get_context()`.
**Decision:** `promote` — this plan is where the promotion actually happens. `HybridRetriever` becomes the sole call site inside `_get_context()` (replacing the direct `self.special_index.get_scored_chunks(question)` / `self.general_index.get_scored_chunks(question)` calls). `SimpleIndex.get_scored_chunks()` is demoted to being `HybridRetriever`'s internal sparse leg, and is only invoked standalone (bypassing fusion) on the Chroma-failure fallback path inside `HybridRetriever` itself (D-06) — it is never run alongside the hybrid path redundantly on a successful query.
**Rationale:** Avoids an "add-alongside" trap where a sparse-only path and a hybrid path both run on every query at double cost with unclear precedence over which result set actually reaches the LLM. `_get_context()` calls exactly one thing per route (`self.hybrid_special` / `self.hybrid_general`); the sparse-only path is purely internal fallback logic inside that one thing, invoked only when dense genuinely fails.
</assumption_delta_decision>
